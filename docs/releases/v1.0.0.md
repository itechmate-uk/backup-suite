First release of Backup Suite with its browser GUI.

Backup Suite backs up folders and MySQL/MariaDB databases from a Linux server
to Google Drive, Dropbox, OneDrive, S3 or any other rclone remote, on a
systemd schedule, within resource limits it enforces itself. It keeps removed
and replaced files as previous versions, and tells you when something fails.

## Install

On the server (Linux with systemd), as the login that will use the GUI:

```bash
curl -fLO https://github.com/itechmate-uk/backup-suite/releases/download/v1.0.0/backup-suite-1.0.0.tar.gz
curl -fLO https://github.com/itechmate-uk/backup-suite/releases/download/v1.0.0/backup-suite-1.0.0.tar.gz.sha256
sha256sum -c backup-suite-1.0.0.tar.gz.sha256
tar -xzf backup-suite-1.0.0.tar.gz
cd backup-suite-1.0.0
sudo ./install.sh --install-deps
```

- `sudo ./install.sh` installs for the whole server (backups run as root and
  can back up any folder under `/home`, `/var/www`, `/srv` and `/opt`).
  `./install.sh` without sudo installs for your login only.
- `--install-deps` installs what is missing (rclone, python3, Node.js 18+,
  curl, acl) with apt-get or dnf. Leave it out to install them yourself.
- The GUI is installed for the user who ran sudo (or `--gui-admin LOGIN`);
  `--no-gui` skips it.

Then, as that login, `~/.local/share/backup-suite-gui/app/scripts/backup-suite-gui-server status`
shows how to connect: a Tunnel Manager profile, launcher scripts for Windows,
macOS and Linux, phone apps, or one `ssh -L` command. In the GUI: add a
destination (Admin → Destinations), set it as the default (Admin → All
settings → `RCLONE_REMOTE_ROOT`), add a backup job, and switch the schedule on.

## Upgrade

Extract a newer release and run `sudo ./install.sh` again (or `./install.sh`
for a user install). The configuration, credentials and resource setup are
kept; on a system install a running backup is waited for, and a failed upgrade
rolls back to the previous version.

## What is in it

- File backups per job and per project folder, with previous versions,
  exclude and volatile patterns, stop files, and files that keep changing
  deferred and reported.
- Database dumps as restore points, database size checks.
- Resource profiles (slow, moderate, fast, adaptive) and a watchdog that
  contains or stops a backup before it hurts the server.
- Notifications through ntfy.
- The GUI: system overview, backup jobs with add, edit, enable, remove and
  back up now, changed and changing files with Exclude…, destinations wizard,
  folder pickers, every setting, runs, logs and audit. It runs as a user
  service and is reached only through an SSH tunnel.
